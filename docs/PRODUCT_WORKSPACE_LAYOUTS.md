# Product workspace orientation

This document describes the intended layout of each Brightdesk product when opened directly.

## Shared frame

The top bar identifies the active product, shows its own original icon and keeps the actions relevant to that product visible. The generic Suite product-management sidebar and welcome banner are not shown in an individual product window. The work area fills the remaining window.

## Product layouts

### Pages
Keep the document canvas centred. The document controls and ribbon sit above the page. Page sizing and orientation belong to document layout controls, not to the application shell.

### Sheets
Keep the formula/name controls directly above the grid. The grid uses the available horizontal space and scrolls within its own work area.

### Decks
Use a slide navigator on the left, a wide presentation canvas in the centre and slide navigation controls below the canvas. The canvas keeps a 16:9 presentation ratio.

### Notes
Prioritise the note editor and its formatting controls. Do not show document, spreadsheet or presentation controls in the Notes workspace.

### Database
Place database/table navigation beside the active record grid. Field and record actions stay near the table they affect.

### Forms
Keep question editing and response review clearly separated. Builder controls should not crowd the form preview.

### Lists
Place saved-list navigation beside the active table. Search, filtering, sorting and record actions belong above the table.

### Planner
Use a board-first layout. Buckets or status columns run left to right, with task cards grouped in their current bucket.

### To Do
Place task views in a compact navigation area. The main area focuses on search, adding tasks, due dates and the active task list.

### Workspace
Keep project navigation separate from the main page/block editor. Project content should use a readable multi-column layout without turning into a Suite launcher.

## Accuracy

A design preview is not a screenshot. Product README files must label design artwork clearly until it has been captured from a verified running build. Do not document a future interaction as a working control.
